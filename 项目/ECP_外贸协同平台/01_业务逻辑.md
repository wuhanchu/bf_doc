# 保沣外贸协同平台（ECP）业务逻辑

> 多角色外贸销售协同平台，覆盖外贸出口全流程：外销单创建 → 托运订舱 → 货代运输 → 报关放行 → 文件归档审批。约 210 个接口，按角色切分控制器。

## 角色

| 角色 | 控制器 | 接口数 | 职责 |
|------|--------|--------|------|
| 销售员 | SalesmanController | 74 | 创建外销单、托运管理、报关单、文件上传审批、K3 同步 |
| 销售管理 | SalesManagementController | 47 | 费用管理、统计报表 |
| 销售支持 | SalesSupportController | 19 | 文件审核 |
| 货代 | ForwarderController | 21 | 接收托运、船期、文件接收上传 |
| 报关行 | CustomsbrokerController | 12 | 报关接收、文件接收上传 |
| 门户 | PortalController | 15 | 登录、公共文件、系统参数 |
| 用户 | UserController | 6 | 个人档案、密码、消息 |

## 核心业务流程

1. **销售员创建外销单**（ForeignSale），关联客户（Customer）
2. **创建托运/装运订单**（Shipment），指定货代供应商（ForwarderProviderId）与报关行（CustomsBrokerProviderId），销售员来源为 K3 装运订单（SellerUserId）
3. **货代接收托运**，维护船期，处理货物（DealUserId 记录处理人），上传运输文件
4. **报关行接收报关**，上传报关文件
5. **文件审批流**：销售员/货代/报关行上传文件 → 上级或销售支持审核（通过/驳回），全程记录 ActionLog
6. **销售管理**查看费用、统计报表（按部门、销售员维度）

## 数据归属与权限模型

- 业务数据按 User ID 归属：`UserId`（创建人）、`SellerUserId`（销售员，K3 来源）、`DealUserId`（货代/报关处理人）、`AddUserId`（录入人）
- 货代/报关行用户通过 `TargetId` 关联供应商（ForwarderProviderId / CustomsBrokerProviderId），`TargetModule = "provider"`
- 数据隔离：货代只能看自己供应商的托运，报关行只能看自己负责的报关单，销售员只能看自己的外销单
- 管理视角（销售管理）按部门查看下属数据（GetDepartmentUsers）

## 外部系统关系

| 系统 | 关系 |
|------|------|
| K3 ERP (BAOFENG20171217) | 装运订单/客户数据同步源，销售员从 K3 选单 |
| QMS | 共用 QMS_Biz 数据库；RabbitMQ 消息解耦（接收 `EMPLOYEE.HANDOVER` 员工交接，发出 `OUTSTOCK.UPDATE`） |
| 云之家 YZJ | 回调通知（4 接口），推送业务消息 |
| 货代/报关行 | 外部供应商用户，通过门户账号登录协同 |
